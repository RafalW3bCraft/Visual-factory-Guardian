# Cinematic landing — design contract

## Reference study
User-supplied `ScreenRecording_10-15-2026 11-50-01_1.mov`: 11.133 seconds, 1180×2556, 60 fps. Inspected at half-second intervals. A phone recording shows a laptop product animation: paired beans open above a grinder, grounds drop into a brewer, liquid visually bridges successive scenes, and a final cup resolves the sequence. Warm cream canvas, oversized narrow serif headlines on the left, small right captions, restrained navigation, physical materials and central vertical alignment. Scrolling appears in the presentation; the underlying implementation cannot be established from this recording. No branding, assets, exact layouts or coffee subject matter are reused. UIZZE catalogue was accessed during initial research, but no applicable screen evidence was available through its text page; the supplied video is the primary visual reference.

## Contract
- Screen job: explain how a flagged product leads to an evidence-supported inspection action.
- User/action: hackathon judge; scroll through seven continuous chapters, then open the existing investigation app.
- Hierarchy: one large statement, one dominant machine/product, one compact evidence annotation.
- Navigation: discreet seven chapter anchors, native page scrolling, final project/GitHub/application links. No scroll hijacking.
- Visual language: warm off-white #F0EEE8, graphite #0B0E12, restrained signal orange #FF7A32 and technical cyan #67C8D8. Condensed sans display, small monospaced annotations, ruled captions, no repeated cards.
- Camera: one persistent canvas and one scrubbed normalized progress; deterministic camera/target, product, inspection light and exploded panels; reversible in both directions.
- Geometry: original procedural steel conveyor, machined flanges, lens assembly, thermal chamber, finned drive motor, sensors, terminal, floor and cable/fastener details. No external model licensing dependencies.
- Provenance: guided synthetic visuals and telemetry; existing thermal-drift-001 values and event identities. The selected P-004 event at 32 seconds follows injected drift at 18 seconds. This is authored temporal alignment, not causal proof. No fabricated localization, confidence, manual citations or AMD performance.
- Required states: loading, WebGL unavailable/context lost, reduced motion, keyboard chapter navigation, hidden-tab pause, offline bundled narrative. Optional evidence detail is native accessible HTML.
- Responsive: desktop asymmetric type/scene composition; mobile upper text/lower reframed scene, smaller pixel ratio and reduced decorative geometry. Reduced motion removes continuous camera travel and ambient animation.
- Forbidden defaults: dashboard hero, glass cards, fake metrics, neon particles, click-dependent story, disconnected canvases.
- Finish gate: build/types, existing unit tests, director tests, browser forward/reverse scroll, desktop/mobile/tablet, fallback/reduced motion, screenshots and measured rendering observations. Preserve existing application and API modules.

## Integration constraints
Inspected main bb1e6e2. Frontend and backend exist; some older docs still describe them as planned. The backend explanation builder is deterministic and manual_citations is empty. AMD adapter code exists but documented evaluation is CPU-only. The landing must remain a self-contained guided simulation. Existing guided frontend flags P-004 only, while backend fixture config also marks later products anomalous; this story deliberately follows P-004 and does not claim parity for all fixtures.
